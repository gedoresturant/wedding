# نظام إدارة قاعات الأفراح — Wedding Halls ERP

نظام ويب عربي RTL لإدارة العملاء والاستفسارات والحجوزات والتحصيلات والمتابعات والقاعات والتقارير. يحتوي المشروع على Backend فعلي باستخدام Express وقاعدة بيانات SQLite، مع عزل بيانات الشركات عن طريق `company_id`.

## المتطلبات
- Windows 10/11 أو Linux
- Node.js 20 أو أحدث
- اتصال إنترنت أول مرة لتثبيت حزم npm والخط من Google Fonts (الخط اختياري)

## التشغيل على Windows
1. فك ضغط الملف.
2. ثبّت Node.js من https://nodejs.org/
3. افتح مجلد المشروع في Terminal / PowerShell.
4. نفّذ:
   ```bash
   npm install
   ```
5. انسخ `.env.example` إلى `.env`، وغيّر `JWT_SECRET` إلى قيمة عشوائية طويلة.
6. نفّذ:
   ```bash
   npm start
   ```
7. افتح `http://localhost:3000`.

يمكنك استخدام `START_WINDOWS.bat` لتشغيل خطوات التثبيت والتشغيل تلقائيًا.

## بيانات تجريبية أول مرة
- معرّف الشركة: `demo-company`
- اسم المستخدم: `admin`
- كلمة المرور: `ChangeMe@12345`

غيّر بيانات الدخول التجريبية قبل استخدام النظام في بيئة حقيقية. البيانات الموجودة تجريبية ويمكن حذفها من قاعدة البيانات بعد أخذ نسخة احتياطية.

## ملاحظات مهمة قبل النشر الفعلي
هذا إصدار أول قابل للتشغيل ويحتاج مراجعة قبول واختبار على بيئة الاستضافة المستهدفة قبل اعتباره جاهزًا للإنتاج. لا تستخدم بيانات عملاء حقيقية قبل تأمين الاستضافة ومراجعة سياسة الخصوصية والنسخ الاحتياطي.

### تعدد الشركات
البيانات التشغيلية مرتبطة بـ `company_id` ويتم تقييد الاستعلامات به. هذه النسخة تنشئ شركة تجريبية واحدة افتراضيًا؛ إنشاء شركات جديدة وإدارة اشتراكاتها تحتاج واجهة Super Admin منفصلة قبل تقديم النظام كخدمة SaaS متعددة الشركات.

### استضافة أونلاين
لا ترفع SQLite على استضافة لا توفر تخزينًا دائمًا أو أكثر من نسخة تشغيلية. للاستخدام الفعلي متعدد المستخدمين، يوصى بنقل قاعدة البيانات إلى PostgreSQL، وتفعيل HTTPS، وتعيين `JWT_SECRET` قوي، وتفعيل نسخ احتياطية تلقائية، واختبار الاستعادة. لا تستخدم الخادم المحلي كخدمة عامة دون هذه الخطوات.

## كارت دعوة الزفاف والتحقق بالـ QR
- عند إنشاء حجز بحالة **مؤكد**، يصدر النظام كارت دعوة أنيق تلقائيًا باسم العريس والعروسة، مع القاعة والتاريخ وكود QR، ويفتح الكارت للطباعة.
- عند تغيير حالة حجز من مبدئي إلى **مؤكد**، يظهر كارت الدعوة تلقائيًا أيضًا.
- موظف الأمن يمسح QR بكاميرا الهاتف؛ تظهر صفحة التحقق باسم القاعة والعريس والعروسة والتاريخ.
- لتسجيل الدخول، يضغط الأمن زر **تأكيد دخول المدعو**. بعد أول استخدام تظهر رسالة أن الدعوة مستخدمة ولا يمكن استخدامها مرة أخرى. هذا يمنع إعادة استخدام نفس الكود، وليس مجرد فتح صفحة الكود.
- تنتهي صلاحية الدعوة عند بداية اليوم التالي لتاريخ المناسبة بتوقيت القاهرة. الحجز الملغي أو غير المؤكد لا يسمح بالدخول.
- يجب أن يكون النظام منشورًا على عنوان يمكن الوصول إليه من هاتف الأمن (دومين أو عنوان شبكة محلية متاح للهاتف). إذا كان النظام يعمل على `localhost` على كمبيوتر الموظف فقط، فلن يستطيع هاتف الأمن فتح رابط QR.
- ثبّت الاعتمادات بعد تحديث المشروع باستخدام `npm install`، ثم شغّل `START_WINDOWS.bat` كالمعتاد.
- تنبيه تشغيلي: يلزم أن يكون الهاتف متصلًا بالإنترنت/الشبكة التي تستضيف النظام وقت المسح. وللاستخدام الفعلي خارج الشبكة المحلية يُفضّل تشغيله عبر HTTPS.


## حسابات الموظفين والصلاحيات والتحصيل
- من حساب المدير افتح **المستخدمون والصلاحيات** وأنشئ حسابين إضافيين بدور **موظف استقبال** و**موظف حسابات**؛ يصبح لديك 3 حسابات: Admin وReception وAccounts.
- **Admin**: صلاحية الإدارة الكاملة.
- **Reception**: تسجيل العملاء والحجوزات واختيار الفقرات ومجموعات المنيو وتأكيد الحجز. اسم موظف الحجز يُحفظ تلقائيًا من الحساب الذي أنشأ الحجز.
- **Accounts**: تظهر له الحجوزات المؤكدة فقط، ويبحث باسم العميل أو العريس أو العروسة أو رقم الهاتف، ثم يسجل دفعة كاملة أو جزئية.
- وسائل التحصيل المتاحة: كاش، إنستا باي، فيزا، محفظة إلكترونية. لا يمكن تحصيل مبلغ أكبر من المتبقي.
- بعد تأكيد التحصيل، يفتح النظام إيصالًا حراريًا بعرض 80mm للطباعة، يحتوي على رقم الإيصال، اسم الشركة والقاعة، العريس والعروسة، التاريخ، إجمالي العقد، المدفوع، المبلغ المستلم في العملية، المتبقي، وسيلة التحصيل، اسم موظف الحجز واسم موظف التحصيل. يمكن إعادة طباعة الإيصال من سجل الدفعات.
- صلاحيات الواجهة وحدها لا تكفي؛ توجد أيضًا قيود على مسارات API، لكن يجب اختبار الصلاحيات في التشغيل الفعلي قبل الاعتماد النهائي.


## الفاتورة التفصيلية للفقرات والشو
- ملف الحجز يعرض العقد الأساسي، إجمالي أسعار الفقرات والشو، إجمالي مجموعات المنيو، إجمالي العقد قبل الخصم، الخصم، المدفوع والمتبقي.
- طباعة بيان الحساب أصبحت فاتورة تفصيلية تشمل اسم كل فقرة، أسماء الشو المرتبطة بها، المدة، وسعر الفقرة، بالإضافة إلى كل مجموعة منيو وسعرها ومكوناتها.
- إيصال التحصيل الحراري 80mm يعرض أيضًا العقد الأساسي، كل فقرة/شو وسعرها، كل مجموعة منيو وسعرها، إجماليات الإضافات، الخصم، إجمالي المستحق، المدفوع والمتبقي.
- ملاحظة: السعر المسجل حاليًا لكل سجل فقرة/شو هو سعر واحد للفقرة/باقة الشو؛ أسماء الشو تظهر كأسماء تفصيلية ضمن هذا السعر، وليست لكل اسم شو قيمة مستقلة منفصلة.


## الإصدار V6: الخصومات والمتعهدون والتقويم والحسابات
### سياسة الخصم
- الخصم يُحسب على سعر الباكدج/العقد الأساسي فقط، ولا يُطبق على الفقرات والشو أو مجموعات المنيو.
- موظف الاستقبال له حد أقصى 20% من سعر الباكدج، والمدير له حد أقصى 30%، والأدمن يستطيع اعتماد خصم أعلى.
- لو أدخل الاستقبال أو المدير خصمًا أعلى من الحد المسموح، لا يُطبق الخصم ولا يُؤكد الحجز ولا تُصدر الدعوة تلقائيًا. يُنشأ طلب موافقة للأدمن.
- الأدمن يوافق أو يرفض مع كتابة السبب الإلزامية. الموافقة تطبق الخصم على الباكدج فقط، والرفض يترك الحجز بدون هذا الخصم. كل طلب ومراجعة وقرار يُسجل في سجل العمليات.
- يوجد حقل خصم واحد للحجز، فلا يتم جمع خصم الاستقبال وخصم المدير على نفس الحجز.

### المتعهدون
- أضف متعهدًا باسم ونوع خدمة ورقم هاتف وسعر افتراضي، مثل التصوير أو رسم الحنة أو التنورة.
- من تفاصيل الحجز يمكن إسناد خدمة لمتعهد مع سعر خاص لهذه الحفلة.
- قسم المتعهدين يعرض إجمالي المستحقات من الخدمات المسجلة، وما تم صرفه، والمتبقي، مع كشف تفصيلي بالحفلات وتواريخها والأسعار وسجل الصرف.
- النظام يمنع صرف مبلغ أكبر من الرصيد المستحق المسجل للمتعهد.

### التقويم
- صفحة تقويم شهرية تعرض عدد الحجوزات بكل يوم والفترات النهارية والمسائية، مع إمكانية فتح اليوم لرؤية القاعات والحجوزات.
- زر التقويم أعلى النظام يفتح ملخص حجوزات اليوم من أي صفحة.

### التكاليف والخزنة والحسابات
- قسم التكاليف لتسجيل تكاليف تشغيل عامة أو ربط التكلفة بحجز وتسجيل التاريخ والتصنيف والموظف.
- قسم الخزنة يجمع تحصيلات الحجوزات، وصرف المتعهدين، والمصروفات، والتكاليف، وحركات الإيراد/الصرف اليدوية، ويعرض صافي الحركة للفترة.
- قسم الحسابات والتحصيل مخصص لتحصيلات الحجوزات، وقسم المتعهدين يحتوي على كشوف مستحقاتهم.

### اختبار التحديث
- اختبارات Node الآلية تتحقق من تركيب ملفات JavaScript ووجود مسارات الخصم والمتعهدين والتكاليف والخزنة والتقويم. الاختبارات الثابتة لا تغني عن تجربة تدفق كامل على قاعدة بيانات تشغيلية قبل الاعتماد المالي الفعلي.


### كتالوج الباكدجات المستند إلى البروشور
- أضف الباكدجات يدويًا من قسم **الباكدجات والأسعار**: الاسم، القاعة (أو كل القاعات)، عدد الأفراد، السعر، والوصف/المكونات.
- عند إنشاء الحجز، اختيار الباكدج يملأ سعر الباكدج وعدد الأفراد تلقائيًا، ويمكن اختيار سعر يدوي بدلًا منه.
- الخصم يُحسب على سعر الباكدج فقط؛ أسعار الفقرات والشو ومجموعات المنيو تضاف خارج الباكدج ولا يدخل عليها الخصم.
- لم أستخرج أسعار الجداول الصغيرة في صور البروشور تلقائيًا لأن دقة النص لا تضمن نقل كل رقم بدقة. أدخل الأسعار من نسخة البروشور الأصلية في كتالوج الباكدجات قبل التشغيل المالي الفعلي.


## الإصدار V7: سعر الوجبة × عدد الأفراد
- لكل مجموعة منيو طريقة تسعير يمكن اختيارها:
  - **سعر للفرد**: سعر الوجبة أو الفرد × عدد الأفراد في الحجز.
  - **سعر ثابت للمجموعة**: يضاف مرة واحدة فقط، للمجموعات التي لها سعر موحد لا يتغير بعدد الأفراد.
- مثال: وجبة سعر الفرد فيها 250 جنيه، وعدد الأفراد 120؛ إجمالي الوجبات = 250 × 120 = 30,000 جنيه.
- عند إنشاء الحجز، يتحدث ملخص الإضافات مع تغيير عدد الأفراد. والحساب النهائي يتم في الخادم أيضًا حتى لا يعتمد على معاينة الشاشة فقط.
- يحفظ النظام في الحجز سعر الفرد وعدد الأفراد وطريقة التسعير والإجمالي ومكونات الوجبة وقت الحجز، حتى لا تتغير الفاتورة القديمة إذا عُدّل سعر المجموعة لاحقًا.
- تفاصيل الحجز وبيان الحساب المطبوع وإيصال التحصيل الحراري تعرض الوجبات ومكوناتها، وسعر الفرد، وعدد الأفراد، والمعادلة، والإجمالي، وباقي تفاصيل العقد والخصم والمدفوع والمتبقي.
- المجموعات القديمة في قاعدة البيانات تُرحّل كـ **سعر ثابت للمجموعة** للحفاظ على حساباتها السابقة. عند إنشاء وجبة جديدة اختَر «سعر للفرد» إذا كان المطلوب ضرب السعر في عدد الأفراد.


## الإصدار V9: إشعارات الخصم وكشوف المتعهدين وتصدير Excel
### طلب الخصم الاستثنائي
- أثناء إنشاء الحجز يظهر مربع واضح: «طلب موافقة الأدمن على الخصم الاستثنائي».
- إذا تجاوز الخصم الحد المسموح للمستخدم، يجب تفعيل مربع الطلب قبل حفظ الحجز. لا يتم تطبيق الخصم أثناء الانتظار، ويبقى الحجز مبدئيًا.
- يصل إشعار داخل النظام لحسابات الأدمن النشطة بطلب الخصم الجديد.
- عند موافقة الأدمن، يُطبق مبلغ الخصم المطلوب تلقائيًا على الحجز. عند الرفض لا يُطبق الخصم.
- يجب كتابة سبب الموافقة أو الرفض. يصل إشعار لصاحب الطلب بنتيجة القرار والسبب وقيمة الخصم المعتمدة إن وجدت.
- زر الجرس أعلى النظام يعرض الإشعارات، مع إمكانية تعليم إشعار كمقروء أو تعليم الكل كمقروء. يجري تحديث عداد الإشعارات دوريًا أثناء فتح النظام.
### المتعهدون والإيصالات
- كشف حساب المتعهد يعرض رقم الحجز، تاريخ الحفل واليوم، الفترة، القاعة، العريس والعروسة، الخدمة، المستحق لكل خدمة، سجل الدفعات، طريقة الدفع، الموظف، والرصيد المتبقي.
- يمكن تصدير كشف كل متعهد إلى CSV متوافق مع Excel.
- بعد تسجيل صرف المتعهد يُفتح إيصال قابل للطباعة، ويشمل اسم القاعة/الشركة، رقم الإيصال، المتعهد والخدمة، المبلغ والطريقة، إجمالي المستحق والمدفوع والمتبقي، اسم الموظف وملاحظات الصرف. ويمكن إعادة طباعة أي إيصال من كشف الحساب.
### تقارير Excel
- تصدير الحجوزات.
- تصدير التكاليف.
- تصدير التقرير المالي الذي يجمع تحصيلات الحجوزات والتكاليف وحركات الخزنة.
- تصدير ملخص حسابات المتعهدين، أو كشف تفصيلي لكل متعهد.
- الملفات بصيغة CSV مع BOM لدعم فتح النص العربي في Microsoft Excel. هذه الملفات متوافقة مع Excel ويمكن حفظها من Excel بصيغة XLSX إذا لزم الأمر.


## الإصدار V10: حدود خصم قابلة للتخصيص لكل مستخدم
### إعداد الصلاحيات
- من المستخدمون والصلاحيات، يستطيع الأدمن تحديد حد الخصم لكل مستخدم بشكل مستقل.
- نوع الحد إما نسبة مئوية من سعر الباكدج الأساسي أو مبلغ ثابت بالجنيه.
- أمثلة: 20% من سعر الباكدج، أو حد أقصى 10,000 جنيه. لا يمكن أن يتجاوز الخصم سعر الباكدج نفسه.
- القيم الافتراضية للمستخدمين الحاليين عند الترقية: مدير النظام 100%، المدير/المدير العام 30%، الاستقبال 20%، الحسابات 0%، ويمكن للأدمن تعديلها.
### تجربة الخصم الاستثنائي
- في نموذج الحجز يوجد اختيار نوع الخصم: نسبة مئوية أو مبلغ ثابت، ثم إدخال القيمة.
- يظهر تنبيه احترافي مباشرة عند تجاوز حد المستخدم، ويوضح الخصم المطلوب وحد الصلاحية والمبلغ المسموح.
- عند حفظ حجز بخصم أعلى من الحد، يُرسل النظام طلبًا تلقائيًا لحسابات الأدمن النشطة مع رقم الحجز، بيانات العميل والعريس والعروسة، القاعة، التاريخ والفترة، عدد الأفراد، سعر الباكدج، قيمة ونسبة الخصم، وحد المستخدم.
- يظل الحجز مبدئيًا ولا تصدر دعوة QR قبل القرار.
- يجب على الأدمن اختيار الموافقة أو الرفض وكتابة السبب. عند الموافقة يُطبق الخصم المطلوب تلقائيًا؛ عند الرفض يبقى الخصم في حدود صلاحية الموظف. في الحالتين يصل إشعار واضح لصاحب الطلب، ويمكنه فتح الحجوزات لاستكمال التأكيد.
- سجل الموافقات والرفض يُسجل في سجل العمليات.


## الإصدار V11: استعادة النسخة الاحتياطية
من صفحة «إعدادات الشركة» يوجد قسم «النسخ الاحتياطي والاستعادة»:
1. اضغط «تنزيل نسخة احتياطية الآن» لحفظ قاعدة البيانات الحالية.
2. لاختيار نسخة سابقة، اختر ملف `.sqlite` أو `.db` تم تنزيله من النظام، ثم اضغط «استعادة النسخة الاحتياطية».
3. يطلب النظام تأكيدًا صريحًا، ويتحقق من ترويسة SQLite وسلامة القاعدة `integrity_check` ووجود جداول النظام الأساسية قبل الاستبدال.
4. قبل الاستعادة، يحفظ النظام نسخة تلقائية من القاعدة الحالية داخل مجلد `data` باسم يبدأ بـ `auto-before-restore-`.
5. بعد نجاح الاستعادة، يتوقف السيرفر عمدًا. شغّل `START_WINDOWS.bat` مرة أخرى وسجّل الدخول من جديد.
6. إذا كان الملف غير صالح، تُرفض الاستعادة ولا يتم استبدال قاعدة البيانات.
تنبيه: الاستعادة تستبدل قاعدة البيانات كاملة بمحتوى الملف المختار؛ اختر النسخة الصحيحة وتأكد من وجود نسخة احتياطية حديثة.


## الإصدار V12: مسميات وظيفية وصلاحيات حرة
- لم تعد إضافة المستخدم مقيدة بقائمة أدوار ثابتة. اكتب المسمى الوظيفي بحرية، مثل: موظف استقبال، مدير استقبال، محاسب، محاسب تكاليف، محاسب عام، مدير حسابات، أو أي مسمى آخر.
- أثناء إنشاء المستخدم أو تعديله، اختر بنفسك الأقسام التي يستطيع الوصول إليها من قائمة الصلاحيات.
- القائمة تشمل لوحة التحكم، العملاء، المتابعات، الحجوزات، التقويم، القاعات، الباكدجات، الفقرات، الوجبات، الحسابات، المتعهدين، التكاليف، الخزنة، موافقات الخصم، التقارير، المستخدمين، سجل العمليات، والإعدادات.
- حد الخصم لكل مستخدم يظل قابلًا للتخصيص كنسبة مئوية أو مبلغ ثابت.
- النظام يتحقق من صلاحية القسم على مستوى الواجهة وطلبات API، ولا يعتمد فقط على اسم الوظيفة.
- عند ترقية قاعدة بيانات موجودة، تُحوّل الصلاحيات القديمة إلى مجموعات مناسبة للدور السابق حتى لا يحصل كل موظف تلقائيًا على جميع الصلاحيات. بعد الترقية راجع صلاحيات كل مستخدم.


## الإصدار V13: البحث عن العميل برقم الموبايل أثناء الحجز
- عند فتح نموذج حجز جديد، اكتب رقم الموبايل في خانة البحث؛ النظام يبحث تلقائيًا داخل عملاء الشركة الحالية.
- إذا وجد الرقم، يختار العميل تلقائيًا ويعرض اسمه ورقمه واسم العريس والعروسة ونوع وتاريخ المناسبة السابقة والقاعة والملاحظات، مع إمكانية مراجعة ملفه.
- تطبيع رقم الهاتف يزيل المسافات والرموز ويقارن صيغ أرقام مصر الشائعة مثل 01... و+20...
- إذا لم يجد الرقم، يظهر نموذج «تسجيل عميل جديد» داخل نفس نموذج الحجز. اكتب اسم العميل وبيانات أصحاب المناسبة، وسيُنشأ ملف العميل تلقائيًا قبل حفظ الحجز.
- البحث يتم داخل بيانات الشركة الحالية فقط، ولا يكشف عملاء شركات أخرى.


## الإصدار V14: إصلاح فتح الحجز والبحث برقم الهاتف
- إصلاح خطأ JavaScript في نموذج الحجز: كان متغير `fields` غير معرّف بعد إضافة واجهة البحث، مما يمنع فتح النموذج عند الضغط على «حجز جديد».
- إدراج خانة رقم الموبايل فعليًا داخل نموذج الحجز، ثم عرض نتيجة البحث أو نموذج تسجيل عميل جديد.
- السماح بفتح حجز حتى لو لم توجد أي سجلات عملاء مسبقًا؛ يمكن إنشاء العميل من نفس النموذج.
- إضافة رسائل واضحة إذا فشل تحميل بيانات نموذج الحجز بدلًا من عدم حدوث شيء.


## الإصدار V15: تبسيط القاعات وإصلاح الهاتف والاستعادة
- نموذج القاعة أصبح يحتوي فقط على اسم القاعة والحالة: نشطة أو خارج الخدمة. يتم حفظ الحالة عند الإضافة والتعديل.
- إزالة نقل التركيز التلقائي من خانة رقم الموبايل إلى اسم العميل؛ يمكن كتابة الرقم كاملًا دون أن ينتقل المؤشر تلقائيًا، مع `inputmode=tel` و`autocomplete=tel`.
- إصلاح استعادة النسخة: السيرفر يفحص النسخة ثم يحفظ نسخة أمان من قاعدة البيانات الحالية ويضع النسخة المختارة كاستعادة معلقة. بعد إيقاف العملية، يطبق التشغيل التالي النسخة قبل فتح SQLite، لتفادي مشاكل قفل الملفات على Windows.
- على Windows يحاول النظام فتح نافذة تشغيل جديدة تلقائيًا بعد الاستعادة. إذا منع النظام التشغيل التلقائي، شغّل `START_WINDOWS.bat` يدويًا.
- قاعدة البيانات الحالية لا تُستبدل بملف غير سليم؛ يتم فحص `integrity_check` والجداول الأساسية أولًا.


## الإصدار V16: عرض القاعات بالاسم والحالة فقط
- صفحة القاعات تعرض عمودين فقط: اسم القاعة والحالة (نشطة / خارج الخدمة).
- اضغط على اسم القاعة لتعديل الاسم أو الحالة؛ زر إضافة قاعة يحتوي على الاسم والحالة فقط.
- لا يتم عرض المكان أو السعة أو أسعار النهاري والمسائي في صفحة إدارة القاعات.


## الإصدار V17: تفاصيل الباكدج واسم القاعة فقط في الحجز
- عند اختيار باكدج يدويًا أو اختيار الباكدج تلقائيًا حسب القاعة وعدد الأفراد، تظهر لوحة بمكونات الباكدج.
- المكونات المعروضة: إيجار القاعة (مكيفة أو Open Area)، دانس فلور، كوشة للعروسين، ليزر موفنج بيم، DJ، تصوير فيديو HD، ترابيزات استيل وكراسي استيل جولد، سنتر بيس، ديكور مدخل، زينة مدخل، شاشات عرض، وتصوير فيديو جميع القاعات بكاميرا مونو HD.
- إذا كان للباكدج وصف إضافي مسجل، يظهر أسفل المكونات.
- قائمة اختيار القاعة داخل نموذج الحجز تعرض اسم القاعة فقط، دون المكان أو السعة أو أي تفاصيل أخرى.


## الإصدار V18: متابعة الاستفسارات وباكدجات القاعات
- عند تسجيل استفسار/عميل جديد مع تحديد «موعد المتابعة»، يُنشأ سجل متابعة تلقائيًا يظهر في صفحة المتابعات، مع اسم العميل ورقمه وموعد المتابعة وتفاصيلها.
- عند تعديل بيانات العميل وإضافة موعد متابعة جديد، يتم إنشاء متابعة إذا لم توجد متابعة معلقة لنفس العميل ونفس التاريخ.
- في نموذج الحجز أصبح اختيار القاعة أولًا. قائمة الباكدجات تبدأ برسالة «اختار القاعة أولًا» ولا تعرض باكدجات قبل تحديد القاعة.
- بعد تحديد القاعة، تظهر فقط الباكدجات النشطة المرتبطة بهذه القاعة تحديدًا. إذا لم تكن هناك باكدجات مرتبطة، تظهر رسالة واضحة بدل عرض باكدجات قاعات أخرى.
- يبقى اختيار الباكدج تلقائيًا حسب عدد الأفراد متاحًا عند وجود شريحة سعر مناسبة للقاعة المختارة.


## الإصدار V19: طلب الخصم الاستثنائي وتقرير الخصومات
- عند تجاوز حد الخصم المسموح للمستخدم، يظهر زر «إرسال طلب للمدير العام» وحقل إلزامي لكتابة سبب الطلب.
- إرسال الطلب يحفظ الحجز بحالة مبدئي، ويطبق مؤقتًا الخصم المسموح فقط، ويرسل إشعارًا للمدير العام بتفاصيل الحجز والخصم والسبب.
- المدير العام يوافق أو يرفض مع كتابة سبب القرار. عند القرار، يُطبّق الخصم المعتمد أو يبقى الخصم ضمن الحد المسموح، ويصل إشعار للموظف؛ يتم تحديث شارة الإشعارات كل 5 ثوانٍ ويظهر تنبيه عند وصول إشعار جديد.
- صفحة طلبات الخصم تعرض سبب طلب الموظف، واسم المدير الذي راجع الطلب، وسبب القرار.
- تمت إضافة تقرير CSV متوافق مع Excel على المسار `/api/reports/discounts.csv` ويظهر زر «تقرير الخصومات Excel» في تقارير الإدارة. يحتوي على رقم الحجز والعميل والقاعة والتاريخ والخصم المطبق والموظف وحالة الموافقة واسم المدير العام وسبب الطلب وسبب القرار.
- تمت إضافة ترحيل تلقائي لعمود سبب الطلب إلى قواعد البيانات القديمة.


## الإصدار V20: إظهار الباكدجات القديمة
